# Аудит автопринятия и подключения — 3 ноября 2026

Выпуск новых версий остановлен по просьбе пользователя. v0.5.22 переведён в черновик, workflow отменён; latest возвращён на v0.5.2. Эти исправления остаются в рабочем дереве и не входят в установленную LM.

## Найдено и исправлено

- Повторная попытка принятия с тем же таймером пропускалась после HTTP 503. Сначала воспроизведено падением интеграционного теста; обработанным считается только успешное принятие. Проверены также отмена ожидающего запроса и освобождение блокировки.
- В снимке AutomationSettings оставался старый IsEnabled. Сохранение метода или профиля могло записать выключенное автопринятие при включённом сервисе. Снимок теперь использует текущий флаг сервиса.
- При ошибке записи включение уже менялось в памяти. Изменение флага выполняется после успешного сохранения.
- В резервном Polling для WebSocket были две задержки по 5 секунд. Убрана первая; отдельная проверка запускает резервный polling без WebSocket-слушателя.
- Отложенная загрузка справочника чемпионов задерживала применение сохранённых настроек и могла заменить новые настройки устаревшим снимком. Настройки применяются до сетевого запроса; результат разрешения ID применяется только к той же ревизии настроек. Учтены запуск приложения и загрузка облачного профиля.
- При недоступном Data Dragon сохранённые ID заменялись пустыми значениями. Загрузка профилей теперь завершается ошибкой до изменения ID; старт сохраняет рабочие ID, а сохранение новых настроек сообщает об ошибке.
- Страница настроек использовала собственный default Polling, расходившийся с backend. Теперь она читает фактический метод из AutomationSettings.
- Непосредственный вызов принятия теперь проверяет выключенный флаг и для UIA.

Ранее исправленный обязательный запрос к необязательному `/lol-service-status/v1/shard-data` также покрыт повторным прогоном. Его 404 больше не останавливает Polling и WebSocket.

## Проверки и их границы

- Rust unit-тесты: сохранение ID при недоступном каталоге, ревизии настроек, текущий IsEnabled, политика режимов, ARAM, безопасное восстановление, хранение и другие существующие проверки.
- Синтетический LCU: реальные локальные HTTP/WebSocket, 404 необязательного API, 503 и отмена принятия, переподключение/смена порта, ARAM-скамейка, Unglitch и диагностика без чтения настоящего UI.
- Существующие JS-тесты и production-сборка интерфейса.

Это проверка кода и воспроизводимых сценариев, не подтверждение исправления на домашнем ПК. Домашние логи не получены; единственная причина домашнего отказа не установлена. Живые очереди, UIA в League, все режимы, Repair Tools на домашнем провайдере, друзья/передача и синхронизация двух ПК требуют проверок из `docs/home-validation-checklist.md`.
