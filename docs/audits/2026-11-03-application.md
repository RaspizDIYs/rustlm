# RustLM: аудит ошибок — 3 ноября 2026

Выпуск версии остановлен по просьбе пользователя. Этот документ описывает локальное дерево исходников, а не установленную LM или развёрнутый GoodLuck. Компактный визуал и поведение выбора рун в редакторе сохранены.

## Исправления сверх первого прохода автопринятия

1. Экспорт/импорт терял сервер аккаунта. Сервер теперь сохраняется в обоих вариантах экспорта; старые файлы без этого поля остаются читаемыми.
2. При ошибке DPAPI экспорт молча подставлял пустой пароль. Экспорт завершается ошибкой до записи, существующий файл остаётся целым.
3. Ошибка чтения accounts.json превращалась в пустой экспорт. Для экспорта используется строгий снимок, как для хранилища.
4. При редактировании аккаунта с изменённым регистром логина маска пароля могла заместить реальные данные. Поиск сохранённого пароля теперь соответствует регистронезависимой идентификации в хранилище.
5. Два параллельных входа могли перезапускать один клиент и сбрасывать отмену друг друга. Входы сериализованы, повторный запуск отклоняется; отмена при ожидании данных временного доступа сохраняется.
6. RC HTTP 404/500 возвращались как успех. Ошибки HTTP теперь отклоняются; сырые ответы авторизации не попадают в сообщение ошибки. Маркер непринятой EULA сохранён.
7. Недоступность RC могла подтверждать выход из аккаунта и завершать задачу очистки временного доступа. Состояние авторизации теперь различает неизвестный результат и подтверждённый выход; неизвестные задачи остаются в очереди.
8. Обрезка текста по номеру байта могла вызвать panic на кириллице. Логгер обрезает по символам, диагностический вывод ответов RC и списка чемпионов не копирует тело ответа.
9. Одновременные сохранения страниц рун могли потерять одну страницу; повреждённый JSON мог перезаписаться пустым набором. Добавлены блокировка, атомарная запись и восстановление из проверенной копии; редактирование непрочитанных данных завершается ошибкой.
10. Настройки метода и AutomationSettings записывались раздельно. Связанные значения теперь сохраняются одной операцией; память меняется после успешной записи.
11. Разведка скрывала ошибки сохранения ключа/региона, а загрузка настроек оставляла кэши от прежнего региона. Запись ключа и региона атомарная; ошибка возвращается вызывающему коду; кэши очищаются при обновлении и загрузке конфигурации.
12. Пресеты конфигов принимали ID с выходом из каталога; запись индекса могла потерять параллельное изменение. ID проверяется до работы с путём, операции сериализованы, файлы записываются атомарно. Повреждённый индекс больше не считается пустым, JSON проверяется перед применением.
13. При смене назначенной роли уже выставленные флаги рун/заклинаний не давали применить профиль новой роли. Флаги сбрасываются при переходе между профилями режим/роль; повторные события того же профиля ничего не сбрасывают.
14. Чтение друзей могло пересечься со сменой Riot-аккаунта и опубликовать список под неверным PUUID. После чтения списка проверяется, что текущая идентичность не изменилась.
15. Repair Tools мог подготовить адреса hosts по повторному замеру, но передать ID предыдущего отчёта. Адреса и ID теперь берутся из одного подтверждённого отчёта.
16. После прерванной смены ключа облака кнопка подключения другого ПК могла показать старый код. При незавершённой ротации сначала проверяется ключ актуального удалённого документа; при невозможности проверки код не выдаётся как подтверждённый.

Предыдущие исправления автопринятия описаны в `2026-11-03-auto-accept.md`.

## Доказательства

- Экспорт: два регрессионных теста сначала упали на старом коде (`artifacts/audit-storage-before.log`), затем прошли. Проверены обычный и зашифрованный файлы, сервер, пароль, заметка и закрепление, а также сохранность прежнего файла при ошибке.
- 114 Rust-тестов прошли. Проверены параллельные записи, повреждение файлов, отказ записи, смена профиля, восстановление после ротации, криптографическая привязка к пользователю и существующие политики.
- 6 сценариев HTTP/WebSocket тестового LCU/RC прошли отдельно. Публичный сетевой smoke-test остаётся отключённым, как и прежде.
- 45 JS-тестов прошли; production-сборка интерфейса и `cargo check --features goodluck-test` прошли.
- Ручные адреса, системные DNS/hosts, реальный Zapret и данные аккаунтов пользователя в рамках тестов не изменялись. Тесты используют временные файлы и локальный симулятор.

## Покрытие и пределы

| Подсистема | Что проверено локально | Что этим не подтверждается |
|---|---|---|
| Аккаунты | Хранение, удаление, повторный импорт, экспорт и слияние | Реальный вход через окно League |
| Автоматизация | Правила режимов/ролей, готовность, смена профиля, таймеры ARAM и переподключение | Все реальные очереди и реальная UIA-кнопка принятия |
| Unglitch | Защищённые фазы, ограничение повторов, синтетическое восстановление | Реальный зависший CEF/драйвер/анимация |
| Repair Tools | План/откат, защита от изменений, скриптовые помощники и логика отчётов | ISP/DPI дома и работа реального winws |
| Облако | Шифрование, слияние, конфликт удаления, незавершённая ротация | Физические два ПК и работа production backend |
| Друзья/передача | Объединение списков, сопоставление идентичности, очередь очистки | Взаимодействие двух настоящих пользователей |
| Разведка | Разбор ответов, конфигурация и кэши | Живой Riot API и полнота данных скрытого лобби |
| Конфиги/руны | Пути, атомарность, повреждение и атрибут read-only | Применение в установленной игре |
| Интерфейс/логи | JS-тесты, типы, сборка и Unicode | Визуальная ручная проверка native-окна |

Гарантия отсутствия всех багов из этого аудита не следует. Домашний чек-лист остаётся обязательным для подтверждения реальной работы; особенно важно перепроверить Polling на том ПК, где был отказ.
