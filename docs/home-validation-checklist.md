# RustLM — проверка дома на настоящем клиенте

Состояние на 5 ноября 2026 года. Это список приёмки, а не утверждение, что
всё ниже сломано или вообще никогда не работало. Если нет подтверждения именно
для новой сборки, пункт остаётся открытым. Тесты на снимках API не заменяют League.

## Что уже известно

- 5 ноября пользователь подтвердил, что автопринятие дома снова работает. Метод и точный номер проверенной сборки в этом сообщении не уточнены; автопик и автобан пользователь не проверял.
- Пользователь подтвердил сбой Polling дома в 0.5.21. Локально воспроизведена регрессия запуска при 404 вспомогательного status API; исправление 0.5.22 проверено симулятором для Polling и WebSocket, дома нужна повторная проверка.
- Исходный Unglitch работал по подтверждению пользователя; переписанный вариант и автоматическое восстановление на настоящей League не подтверждены.
- Для исправления 0.5.22 прошли 115 Rust-тестов, 7 сквозных тестов с синтетическим LCU и 45 JS-проверок. Это локальные проверки, не игровые; релизная сборка проверяется отдельно.
- Repair Tools прогонялся на рабочем ПК и другом провайдере. Есть логи, но нет подтверждения полного восстановления на домашнем подключении при реальной проблеме.
- Скриншоты друзей, аккаунтов и прочих экранов подтверждают отдельные состояния интерфейса, а не весь сценарий.
- Для Разведки нет достаточного подтверждения полного живого сценария. Помечаем «требует проверки», а не «точно не работает».
- Внешняя диагностика UI Automation и задержек действий включена в 0.5.21, но покрытие настоящего клиента не проверено. Pengu, внедрение DLL и доступ к DOM не используются.

## Перед началом

- [ ] P01. **Проверить саму сборку.** Установить релиз 0.5.22 и проверить переключатель «Автовосстановление» и блок диагностики в Unglitch. Версия 0.5.21 содержит подтверждённую регрессию автопринятия; её не считать успешным домашним прогоном. Записать источник EXE и его SHA-256.
- [ ] P02. Записать Windows, версию League, сервер RU/EUW, способ запуска LM, VPN и точный BAT Zapret. Без паролей, токенов и кода хранилища.
- [ ] P03. Сохранить отдельный экспорт аккаунтов и копию настроек, проверить возможность их прочитать. Код хранилища хранить отдельно от отчёта.
- [ ] P04. Первые проверки автоматизации проводить в доступной тренировке/лобби/игре без рангового риска. Не создавать додж специально ради теста.
- [ ] P05. Сначала отключить автоматику, которая не нужна в данном сценарии: так видно, что именно проверяется.

## 1. Аккаунты и вход

- [ ] A02. «Из клиента» после настоящего входа — обновляются Riot ID, аватар, ранг и корректный PUUID, а заметки и пароль сохраняются.
- [ ] A03. «Из GoodLuck» повторно — не появляются лишние дубли уже существующего аккаунта; RU/EUW/EUW1 обрабатываются согласованно.
- [ ] A04. Удалить ненужную импортированную запись, дождаться фоновой синхронизации, обновить список и перезапустить LM — запись сама не возвращается.
- [ ] A05. Явно импортировать удалённую запись снова — преднамеренное повторное добавление работает.
- [ ] A06. Одновременно изменить заметку/закрепление и обновить профиль — фоновое обновление не затирает правку.

- [ ] A08. Показ/скрытие логинов, поиск, сортировки, закрепление и порядок переживают перезапуск; вход остаётся отдельной кнопкой рядом с меню действий.

- [ ] A12. League уже запущена: повторный вход/смена аккаунта не создаёт лишние экземпляры и не сообщает об успехе для прежнего аккаунта.

## 2. Автопринятие — отдельно от пиков и ролей

Роли относятся к автопику/автобану. У автопринятия проверяются метод и доступность
самого подтверждения игры. Для режимов без ready-check не ждать несуществующий экран.

- [ ] Q01. **Polling:** включить метод, найти игру — принимается один раз; повторный поиск работает без перезапуска LM.
- [ ] Q02. **WebSocket:** те же два последовательных поиска — событие принимается; нет пропуска, двойной попытки и зависшего флага ожидания.
- [ ] Q03. **UIA:** на открытом настоящем окне нажимается именно доступная кнопка принятия; посторонние кнопки не затрагиваются. Отдельно проверить поведение свёрнутого окна.
- [ ] Q04. Переключить методы в работающем LM — действует новый метод, а не только сохраняется подпись настройки.
- [ ] Q05. Выключить автопринятие — следующий ready-check не принимается автоматически; включить обратно — работает снова.
- [ ] Q06. Доступные обычная/ранговая, ARAM, Хаос и Арена — по одной проверке ready-check, если он есть.
- [ ] Q07. Работа LM в трее/при скрытом окне — фоновое автопринятие сохраняется, хотя UI-опросы могут приостанавливаться.
- [ ] Q08. Перезапуск клиента между поисками и новая авторизация/порт — LM восстанавливает приём событий; WebSocket-сбой не оставляет автопринятие навсегда выключенным.

## 3. Автоматизация чемпионов и раскладки

- [ ] C01. **Обычные/ранговые: все пять ролей.** Для топа, леса, мида, ADC и поддержки настроить разные приоритеты; применяется назначенная клиентом роль.
- [ ] C02. Автопик/автобан включаются общими переключателями для обычных ролей; выбранные чемпионы при этом остаются разными по ролям.
- [ ] C03. Запасные пики: основной недоступен/забанен/занят — выбирается допустимый следующий; пустая роль не получает чужой профиль.
- [ ] C04. Пик/бан подтверждается в настоящей сессии; уже завершённое действие не повторяется. Предвыбор союзника не банится автоматически.
- [ ] C05. Смена роли/новая сессия во время ожидания — отложенное действие старой сессии не выполняется.
- [ ] C06. Лес в обычном режиме — ровно одна Кара, второе заклинание сохраняется; на других ролях Кара не навязывается.
- [ ] C07. Разрешённые заклинания действительно применяются, ограничения режима соблюдаются; отклонённая клиентом команда не вызывает бесконечный цикл.
- [ ] C08. Руны: создать, сохранить, выбрать и применить — клиент реально использует нужную страницу; чужие страницы не удаляются. Поведение повторного выбора ветки сохраняется как в игре.
- [ ] C09. Ошибка сохранения страницы не закрывает редактор и не уничтожает правки. Проверить отзывчивость нескольких быстрых нажатий.
- [ ] C10. **ARAM:** свои карточки, выбор приоритетного доступного чемпиона, ожидание открытия общей скамейки, обмен только на улучшение приоритета.
- [ ] C11. **ARAM: Хаос:** те же ограничения карточек/скамейки, руны не записываются, используются только разрешённые заклинания.
- [ ] C12. ARAM/Хаос: 1, 3 и 30 приоритетов; работает последний приоритет, удаление конкретной иконки и сохранение порядка.
- [ ] C13. Союзник забрал чемпиона до нашего обмена или время истекло — LM оставляет текущего чемпиона и не шлёт старый обмен.
- [ ] C14. **Арена, когда доступна:** отдельный профиль, реальный пик/бан, выбор по приоритетам/наковальне согласно настройке; ручной Bravery остаётся ручным. Недоступные руны/заклинания не записываются.
- [ ] C15. При отключённом автопринятии автопик/бан, если включены, продолжают работать. Обратный случай: принятие включено, пики выключены — ручной выбор не трогается.

## 5. Unglitch — ручной и автономный

- [ ] U01. Штатная перезагрузка интерфейса вне игры — появляется новый интерфейс, окно и API отвечают; существование процесса само по себе не считается полным успехом.
- [ ] U02. «Скрыть окно» → «Открыть окно» — фон League сохраняется; автономный режим сам не открывает намеренно скрытое окно.
- [ ] U03. Ручной перезапуск рендера — затрагивается только рендер выбранной установки, а не игра, Riot Client, Vanguard или другая установка.
- [ ] U04. Опасные ручные действия запрашивают подтверждение; работающая другая операция блокирует параллельный запуск.
- [ ] U05. Переключатель автовосстановления сохраняется после перезапуска; наблюдение работает в трее.
- [ ] U06. Нормальная длительная загрузка при живом окне не вызывает перезапуск. Есть стартовая пауза и подтверждение признаков зависания несколькими проверками.
- [ ] U07. Поиск, ready-check, выбор чемпионов, матч, переподключение и неизвестная стадия — **автоматическая перезагрузка не выполняется**.
- [ ] U08. При настоящем зависании в разрешённом лобби — одна мягкая попытка, проверка результата и запись в журнал. Если зависание не воспроизводится естественно, оставить пункт открытым.
- [ ] U09. Если попытка не помогла — нет бесконечного цикла, автоматического убийства процессов или автоматического скрытия окна.
- [ ] U10. Восстановление соединения с API не требует перезагрузки здорового интерфейса.
- [ ] U11. Отсутствие прав/неоднозначные процессы/неизвестный рендер — отсутствие данных, а не ложное доказательство зависания.

## 5.1. Внешняя диагностика экранов (без Pengu)

Эта часть не видит весь DOM, все анимации и все запросы самой League. Она
читает доступные элементы через Windows UIA и измеряет собственные запросы LM.
Недоступность UIA — ограничение наблюдения, не доказательство зависания игры.

- [ ] D01. В Unglitch снять замер: без League — «Ждём League», со скрытым окном — соответствующее состояние, без доступа к дереву — «Нет данных»/«Мало данных».
- [ ] D02. На настоящем клиенте проверить лобби, выбор чемпионов, статистику и «Ремесло»: какие экраны и индикаторы действительно раскрываются через UIA. Записать покрытие, не ставить PASS всем экранам по одному доступному элементу.
- [ ] D03. Долгая загрузка: если индикатор доступен, длительность растёт; исчезновение индикатора, смена экрана и сон ПК сбрасывают её. Ожидание само не запускает ремонт.
- [ ] D04. Запросы LM к статистике/рунам/выбору отражаются в соответствующих разделах с длительностью и HTTP-результатом. Быстрый ответ не называется подтверждением здорового UI.
- [ ] D05. Собственный автопик/автобан LM: «Ответ получен» отличается от «Подтверждено LCU»; последнее возникает только после имеющейся проверки результата выбора. При отмене/неподтверждённом результате нет ложного успеха.
- [ ] D06. Обычное отсутствие сессии (GET 404) не заполняет историю ошибками; медленные/ошибочные запросы видны, история и память ограничены.
- [ ] D07. Диагностические проверки не кликают, не меняют фокус, не открывают окна и не повторяют открытие сундуков/крафт/покупки. Автовосстановление Unglitch отключить отдельно и проверить, что диагностика продолжает работать.
- [ ] D08. Экспорт отчёта: только категории, счётчики, время и HTTP-коды; нет сырых URL, query, тел запросов/ответов, текста полей или данных аккаунтов.
- [ ] D09. Нечитаемый/зависший UIA-провайдер не вешает LM и не создаёт новые потоки каждые 15 секунд; остальное приложение остаётся отзывчивым.

## 6. Repair Tools — именно на домашнем провайдере

- [ ] R01. Определение папки и **точного BAT**, включая реальные ALT11/ALT13; выбранное имя соответствует запущенной стратегии, нет смещения индексов.
- [ ] R02. Zapret выключен → запуск выбранного BAT из LM; статус обновляется без ложного зависания и запуска меню service.bat вместо стратегии.
- [ ] R03. VPN/прокси включён, Zapret выключен, запущена другая стратегия — видны отдельные корректные состояния, мастер не начинает неподходящий замер молча.
- [ ] R04. UAC принят, отклонён или не появился — понятная ошибка/тайм-аут, интерфейс остаётся управляемым, результат запуска проверяется фактически.
- [ ] R05. Исходный сетевой замер без VPN/Zapret → замер с выбранным Zapret; сравниваются сопоставимые адреса, IP и порты на одном подключении.
- [ ] R06. DNS A/AAAA/CNAME, TCP, TLS и HTTPS классифицируются отдельно: нет IPv6-маршрута ≠ недоступна вся Riot; Cloudflare-отказ ≠ сломан DNS; технический алиас ≠ отдельный HTTPS-сервис.
- [ ] R07. Применение добавляет необходимые правила в выбранную стратегию и списки; исходные общие настройки и другие установки Zapret не повреждаются.
- [ ] R08. Перезапуск после применения не висит; действуют новые правила, а service manager и LM не показывают противоречивые состояния.
- [ ] R09. Переключение «Исходная / С настройкой Riot» применяет нужный вариант; откат восстанавливает исходные файлы.
- [ ] R10. Отмена в процессе и ошибка после частичного применения — откат завершается, сохранённые копии доступны после перезапуска LM.
- [ ] R11. Резервные копии/отчёты хранятся в папке LM/Repair Tools, новые мусорные папки в Zapret не множатся.
- [ ] R12. Изменение hosts выполняется только в предусмотренном сценарии подтверждённой проблемы DNS; существующие записи сохраняются, неподтверждённые/частные адреса не добавляются.
- [ ] R13. После изменения проверить **реальный вход RU/EUW, чат и клиент**, затем отдельно матч/UDP/голос, если используются. Успешный HTTPS не подтверждает эти функции.
- [ ] R14. Если дома всё уже работает, проверить диагностику и откат; результат «проблема не воспроизведена», а не «ремонт доказан».

## 7. Два ПК и зашифрованное хранилище

- [ ] V01. Создать хранилище, сохранить код; первый ПК выключить. Второй подключается сохранённым кодом без доступа к первому.
- [ ] V02. На обоих ПК до подключения есть разные записи — списки объединяются, локальные уникальные аккаунты не исчезают.
- [ ] V03. Совпадающая запись с разными данными — конфликт не затирается молча; выбранное разрешение применяется правильно.
- [ ] V04. Добавление/изменение заметки/пароля/порядка с рабочего ПК приходит домой; повторить в обратную сторону, без ручного экспорта.
- [ ] V05. Удаление тестовой записи на одном ПК переносится на другой и переживает перезапуск/импорт профиля GoodLuck. Удаление не тестировать на единственной копии нужного аккаунта.
- [ ] V06. Оба ПК меняют разные записи одновременно — независимые изменения сохраняются; одинаковую запись — корректный конфликт, не потеря данных.
- [ ] V07. Один ПК офлайн, на другом изменения; после возвращения сети оба сходятся к согласованному списку без воскресших удалений.
- [ ] V08. Неверный код, неподключённое/выключенное облако и отсутствие хранилища — разные понятные состояния, локальные аккаунты не стираются.

- [ ] V10. Миграция старого облака добавляет отсутствующее и сохраняет локальные совпадения; обычный импорт профилей GoodLuck не путается с зашифрованной синхронизацией.

## 8. GoodLuck, друзья и передача аккаунтов

- [ ] G01. Обычная LM входит через рабочую авторизацию GoodLuck; callback возвращает в приложение, повторный запуск и выход работают, ошибки читаемы.
- [ ] G02. Подключение GoodLuck и автосинхронизация переживают перезапуск; отключение не удаляет локальные аккаунты.
- [ ] F01. Друг GoodLuck виден с аватаром и правильным значком источника. Пустой список действительно пустой, а не скрытая ошибка API.
- [ ] F02. Два пользователя LM, друзья в League, но не в GoodLuck: подтверждённые игровые аккаунты сопоставляются и появляются в списке при включённом обнаружении.
- [ ] F03. Проверить RU/EUW, разный регистр Riot ID, одинаковое имя с другим тегом; посторонний пользователь не сопоставляется по одному имени.
- [ ] F04. Друзья нескольких аккаунтов: фильтр конкретного аккаунта/общий список, последовательное обновление после входа в каждый.
- [ ] F05. Один человек из двух источников не дублируется и не теряет аватар/отметки League и GoodLuck.
- [ ] F06. Выключение обнаружения учитывается; недоступный/неавторизованный клиент не выдаётся за «у вас нет друзей».
- [ ] F07. Входящие заявки: принять/отклонить; меню не содержит обычных друзей. Удаление друга выполняется в нужном списке с подтверждением и не возвращается само.
- [ ] S01. Передача другу и получение от друга видны отдельными компактными блоками; выбран правильный аккаунт и получатель.
- [ ] S02. Получатель может войти, но обычный интерфейс/экспорт не раскрывает ему пароль владельца. Техническая извлекаемость секрета на его ПК не исключается.
- [ ] S03. Ограниченный срок, бессрочная передача и ручной отзыв — доступ LM соответствует настройке. Истечение не обещает принудительно завершить уже открытую сессию Riot.
- [ ] S04. Повторное открытие ссылки, другой пользователь, отозванная/истёкшая передача — корректный отказ без утечки данных.
- [ ] S05. Очистка временных данных после отзыва/срока не удаляет собственную независимую запись получателя и не оставляет тайно рабочий временный доступ после перезапуска.

## 9. Разведка, конфиги и приложение

- [ ] X01. Разведка: вход в настоящее лобби/выбор чемпионов — правильные союзники, доступные противники, ранги и матчи; пустые данные не подменяются чужими.
- [ ] X02. Скрытые имена в ранговом выборе обозначаются честно; запрещённые/недоступные данные не обещаются. Проверить смену лобби и очистку старого состава.
- [ ] X03. Неизвестный Riot ID, отсутствующая история, ограничения API и отключённая Разведка — понятные состояния, нет зависшего запроса и старой информации от предыдущей сессии.
- [ ] K01. Конфиги: обнаружение файла, создание пресета, применение, экспорт/импорт и откат — в League реально меняется нужная настройка, чужой файл не повреждён.
- [ ] K02. Защита read-only и её отключение: клиент сохраняет настройки согласно выбору, есть понятный путь обратно.
- [ ] I01. Маленькое окно и масштаб Windows 100/125/150%: кнопки, поиск, вкладки и таблицы не обрезаны; нижняя панель клиента закреплена, список прокручивается отдельно.
- [ ] I02. Переключатель анимаций применяется и сохраняется, включая подсветку иконок и переходы. Язык и масштаб приложения отдельно отмечены ниже как незавершённые требования, а не готовые настройки.
- [ ] I03. Трей, автозапуск, запуск в фоне, восстановление окна и повторный запуск не создают лишних окон/консолей/экземпляров.
- [ ] I04. Подсказки исчезают при прокрутке; клавиатура, переключатели, закрытие модалок и возврат фокуса работают.
- [ ] I05. Журналы: фильтры, обновление, автообновление, открытие файла/папки, очистка и отчёт разработчику. Не прикладывать секреты, код хранилища и экспорт аккаунтов к обычному отчёту.
- [ ] I06. Нажатие на версию показывает правильную историю; публичное обновление проверять отдельно от локальной замены EXE.
- [ ] I07. 30–60 минут LM в фоне и несколько смен страниц: приемлемые CPU/RAM, нет бесконечных запросов, накопления обработчиков и торможения кликов.
- [ ] I08. При настоящем пустом/сломавшемся окне WebView2 проверить штатное восстановление/сброс из настроек; после перезапуска локальные аккаунты и настройки LM сохранены. Рабочую установку специально не ломать.

## Обсуждалось, но нельзя выдавать за готовый проверенный функционал

- Выбор языка и масштаба самого приложения: в текущей странице настроек соответствующих контролов не найдено. Полная локализация не подтверждена; это отдельное незавершённое требование.
- Наблюдение за всеми внутренними запросами League, DOM, произвольными CSS-анимациями и точечное восстановление «Ремесла»: не реализовано внешней диагностикой. Нет Pengu/CEF-доступа; UIA может раскрывать лишь часть элементов.
- Исправление настоящего провайдерского сбоя и доказательство работы матча/UDP: нельзя подтвердить одной успешной сетевой проверкой, если исходная проблема не воспроизведена.
- Доступные только сезонно режимы и редкие зависания: BLOCKED до появления сценария, а не PASS по аналогии с другим режимом.

## Порядок на один вечер

1. Зафиксировать EXE и сделать копии: P01–P05.
2. Вход и профили: A01–A04, A09–A10; базовые настройки/трей: I01–I04.
3. Автопринятие: Q01–Q05; затем профили ролей/раскладки и доступные режимы: C01–C15.
4. Соединение между играми: L01–L07; ручной Unglitch вне критических фаз: U01–U05.
5. Repair Tools без намеренного нарушения рабочей сети: R01–R11, R14. Реальный ремонт остаётся открытым до воспроизведения проблемы.
6. Отдельная сессия со вторым ПК: V01–V10. Можно заранее сохранить код, онлайн одновременно нужен только для отдельных конкурентных сценариев.
7. Отдельная сессия с другом: F01–F07, S01–S05. Арена и реальные зависания могут потребовать другого дня — не ставить галочку без проверки.

## Как фиксировать результат

Для каждого пункта: `ID | PASS / FAIL / BLOCKED / НЕ ПРОВЕРЕНО | время | сборка |
сервер/режим/роль | что сделали | ожидание | что получилось | файл лога`.
При BLOCKED указать причину: нет второго ПК, друга, режима, настоящего сбоя или
функция ещё в разработке. Недоступный сценарий не считается ни успехом, ни багом.

При явной потере данных, неверном аккаунте или вмешательстве в неподходящую
стадию остановить именно проблемную автоматику, сохранить отчёт и копии. Не
продолжать ранговые проверки, надеясь, что следующая попытка исправит причину.
