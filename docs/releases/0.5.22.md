# RustLM 0.5.22 — исправления автопринятия и сохранности данных

## Что исправлено

- **Автопринятие:** Polling и WebSocket запускаются при отсутствии вспомогательного status API; исправлены повтор после HTTP-ошибки и отмены запроса, пропуск следующего лобби при совпавшем таймере и лишняя задержка резервного Polling.
- **Автоматизация:** настройки применяются до загрузки справочника чемпионов; поздний ответ не затирает новые изменения. При смене роли применяются нужные руны и заклинания, сохранённые ID не теряются при недоступном справочнике.
- **Вход и Riot Client:** параллельные входы не конфликтуют, ошибка запуска League возвращается пользователю. HTTP-ошибки и недоступность API не считаются успешным действием или подтверждённым выходом.
- **Аккаунты:** экспорт/импорт сохраняет сервер. При ошибке чтения или расшифровки прежний файл экспорта остаётся целым; редактирование регистра логина сохраняет пароль.
- **Руны и конфиги:** атомарное сохранение, защита от конкурирующих записей, восстановление рун из резервной копии, проверка ID пресетов и JSON перед применением.
- **Настройки и разведка:** связанные значения сохраняются вместе, ошибки записи не скрываются, кэши очищаются при смене конфигурации. Исправлена обработка ошибки отключения автозапуска Windows.
- **Облачное хранилище:** после прерванной смены ключа выдаётся проверенный код подключения; получение кода не запускает слияние аккаунтов и не блокируется конфликтами записей.
- **Друзья:** при чтении списка проверяется, что Riot-аккаунт не сменился.
- **Repair Tools:** адреса для hosts и подтверждающий отчёт относятся к одному замеру.
- **Логи:** устранена ошибка обрезки кириллицы, ответы авторизации Riot не копируются в ошибки. Компактный визуал и существующие возможности сохранены.

## Проверки

Прошли 115 Rust-тестов, 7 сценариев локального LCU/RC, 45 JS-тестов и проверка сборки с `goodluck-test`. Публичный релиз использует production GoodLuck (`gltournament.ru`).

Это подтверждает локальные сценарии; живые очереди League, UIA, домашний провайдер и синхронизация двух физических ПК требуют проверки. [Домашний чек-лист: 119 сценариев](https://github.com/RaspizDIYs/rustlm/blob/v0.5.22/docs/home-validation-checklist.md) также приложен к релизу.
